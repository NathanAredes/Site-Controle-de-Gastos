Entendido perfeitamente! Essas são excelentes perguntas e mostram que você já está pensando como um verdadeiro analista de sistemas. No mundo real, essas dúvidas são resolvidas na fase de Alinhamento de Regras de Negócio.
Vamos responder cada um dos seus pontos e ajustar os nossos requisitos:
1. Campos Obrigatórios e "Dinheiro para o Futuro"
Para evitar que os dados fiquem incompletos, o ideal é que Descrição, Valor, Data e Categoria sejam obrigatórios.
Sobre o campo "Tipo", na engenharia financeira de software, investimentos e economias são tratados de uma forma especial. Se você separa R$ 500 para o futuro, esse dinheiro não sumiu (como um gasto com alimentação), ele mudou de lugar. A Solução de Negócio: Adicionaremos um terceiro tipo. O seu campo "Tipo" terá três opções: Receita, Despesa e Investimento/Reserva. Como isso afeta o saldo: Quando você marcar como "Investimento", o sistema vai entender que aquele dinheiro saiu do seu saldo livre do mês, mas foi para o seu painel de metas/futuro.
2. O que é "Receita"?
Em termos financeiros e de programação, Receita é toda e qualquer entrada de dinheiro no seu bolso. Exemplos: O seu salário, o pagamento de um freela, um dinheiro que você recebeu de presente, ou o rendimento de um investimento que voltou para a sua conta. Se o seu saldo aumentou, a origem disso é uma Receita.
3. Atualização do Saldo [RF-003]
Sim, exatamente isso! No desenvolvimento web moderno, usamos o JavaScript para monitorar o formulário. No momento em que você clicar no botão "Salvar", o JavaScript vai pegar o valor digitado, enviar para o banco de dados e, na mesma hora, atualizar o número do saldo na sua tela, sem que você precise atualizar a página (F5).
4. Gestão Avançada de Categorias (O "CRUD" de Categorias)
O que você descreveu (adicionar, remover, editar e listar em um pop-up) na programação é chamado de CRUD (Create, Read, Update, Delete). Essa é uma funcionalidade excelente para o seu portfólio!

Como engenheiros, o nosso objetivo agora é desenhar as tabelas do seu banco de dados. Como você determinou que quer poder criar, editar e deletar categorias, nós não podemos simplesmente salvar a categoria como um texto qualquer. Se você digitar "Alimentação" em um gasto e depois decidir mudar o nome da categoria para "Comida", o sistema quebraria se tudo fosse texto puro.
Para resolver isso de forma profissional, usaremos um conceito chamado Banco de Dados Relacional. Vamos criar duas tabelas que conversam entre si.

IA
O Modelo de Dados do seu Sistema
Imagine que o seu banco de dados terá duas planilhas separadas, mas ligadas por um "fio invisível":
1. Tabela categorias (O catálogo de opções)
Esta tabela vai guardar apenas os nomes das categorias que você criar no seu pop-up.
• id (Número único): O identificador de cada categoria (ex: 1, 2, 3). É gerado automaticamente.
• nome (Texto): O nome que você escolher (ex: "Alimentação", "Lazer").
2. Tabela transacoes (O histórico financeiro)
Esta tabela vai guardar cada lançamento que você digitar no formulário principal.
• id (Número único): O identificador do gasto.
• descricao (Texto): O nome da transação (ex: "Supermercado").
• valor (Decimal): O valor em dinheiro (ex: 150.50).
• data (Data): O dia do gasto.
• tipo (Texto): Restrito a três opções: 'receita', 'despesa' ou 'investimento'.
• categoria_id (Número): Aqui está o segredo. Em vez de escrever "Alimentação", o banco vai salvar apenas o id da categoria correspondente (ex: 1).
Se no futuro você mudar o nome da categoria 1 de "Alimentação" para "Mercado", todas as suas transações se atualizam automaticamente, porque elas apontam para o id 1 e não para o texto!, ou seja, O campo categoria_id, da tabela de transações, "aponta" para o id da tabela de categorias.

A Estrutura de Pastas Profissional
Abra o VS Code, crie uma pasta no seu computador chamada controle-financeiro e, dentro dela, monte a seguinte estrutura de arquivos. Você pode criar esses arquivos vazios por enquanto:
text
controle-financeiro/
├── index.html          <-- Sua página principal (o Dashboard com gráficos)
├── lancamentos.html    <-- A página com o formulário para digitar e a tabela
├── categorias.html     <-- A página/pop-up para gerenciar as categorias
├── css/
│   └── style.css       <-- Toda a estilização e visual do seu site
└── js/
    ├── app.js          <-- O "cérebro" JavaScript que vai conectar tudo
    └── banco.js        <-- Arquivo exclusivo para falar com o banco de dados
O que cada arquivo vai fazer?
• Separar HTML de CSS e JS: Essa organização (colocar estilos na pasta css e scripts na pasta js) é uma boa prática fundamental. Ela garante que se você precisar mexer no visual, você mexe apenas no CSS, sem risco de quebrar a lógica do JavaScript.
• banco.js separado: No futuro, quando conectarmos o seu site ao banco de dados (como o Supabase), todas as configurações de banco vão ficar guardadas apenas aqui dentro. Se um dia você decidir mudar de banco de dados, você só altera esse arquivo, e o resto do site continua funcionando igual.
